## Neu

- **Ereigniskatalog** (#670): Was im DMS passiert, steht jetzt an einer Stelle – Mappen (angelegt, gespeichert, verknüpft, Notiz, Dokument hochgeladen, gelöscht, endgültig gelöscht, wiederhergestellt), **Frist erreicht**, für Personen (neue Aufgabe, neue Post, neuer Favorit), Benutzer (Abwesenheit, gesperrt, deaktiviert, aktiviert) und Verarbeitung (Volltext fertig, Datei umgewandelt, Archivfassung erstellt, Erkennung fertig). Pakete, Webhooks und die kommenden Automatisierungen nehmen ihre Ereignisse aus diesem Katalog. Ein Ereignis enthält nur Kennungen, Feldschlüssel und Datum – nie Inhalte.
- **Pakete mit Code** können jetzt auf Mappen reagieren: `mappe.angelegt`, `mappe.geaendert`, `mappe.geloescht`, `mappe.wiederhergestellt` und `frist.erreicht`, jeweils für die eigenen Mappentypen, die das Paket im Manifest unter `code.mappentypen` nennt. Die Vorschau bei der Installation zeigt sie mit „– zu: *Typen*“. Schnelle Folgen von Änderungen an derselben Mappe kommen als ein Ereignis.
- **Frist erreicht** kommt je Mappe, Feld, Datum und Zeitpunkt (Erinnerung, Tag selbst) genau einmal – auch mit mehreren Servern und nach einem Neustart.
- **Werkbank → Pakete → *Paket*** zeigt beim Paket-Läufer, wann zuletzt ein Ereignis zugestellt wurde, welche Ereignisse das Paket abonniert hat, und unter **Welche Ereignisse es gibt** den ganzen Katalog.
- Beispiel-Mappen, Demo-Daten und eine Wiederherstellung lösen keine Ereignisse aus.

## Handbuch

- Administratorhandbuch: Pakete → Ereignisse → **Ereignisse zu Mappen**, **Frist erreicht**.
- Entwicklerhandbuch: Aufbau → **Ereigniskatalog** (Regeln, Abnehmer, Auslöser); Pakete mit Code → `code.mappentypen` und die neuen Ereignisse.

## Technik

- Migration `060_ereignisse.sql`: Ausgangskorb `ereignisse` (mindestens einmal, feste Ereignis-Id, Sperre für mehrere Server, Bündelung) und `frist_meldungen`.
- `shared/src/ereignisse.ts` (Katalog), `server/src/ereignisse.ts` (Verteiler); `Dienst.ereignis`, `Dienst.mitAusloeser`, `Dienst.ohneEreignisse`.
- Ereignisse an Pakete werden beim Wiederholen nicht doppelt angelegt.
- Tests: `server/test/ereignisse.test.ts`, PostgreSQL in `server/test/pg.test.ts`.
- Keine neue Abhängigkeit.
